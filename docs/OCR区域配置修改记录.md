# OCR 区域识别配置修改记录

> 项目：CYZLZDH（电梯检验记录 / 报告转记录工具）
> 配置文件：`src/CYZLZDH.App/OcrZoneConfig.json`
> 解析引擎：`ZoneOcrParser`（腾讯云 GeneralAccurateOCR 行级坐标 + 预定义区域抽取）
> 提交：`9fb32f4` · 分支：`feature/zone-ocr`

---

## 一、背景与机制

- 所有区域坐标基于**基准 800×1100**（`OcrZoneConfig` 的 `imageWidth/imageHeight` 仅作坐标基准标注）。实测**腾讯云 OCR 返回的是原始图像坐标（1565×1020）**，`ZoneOcrParser` 直接拿原始坐标匹配 zone，并未按基准尺寸缩放，`ZoneOcrService` 本身也不做 resize。配置里的 800×1100 不是归一化输入，切勿在重试/裁剪逻辑里再按它做缩放映射（见第五节）。
- 字段抽取按文字**中心点**是否落入区域来采集：区域宽度不会“裁掉”文字，但中心点滑出区域 / 落入区域间隙时会**整段漏识别**。
- 本次会话对 `OcrZoneConfig.json` 做了 3 处字段区域调整（含此前已修的 `UserName`），均已随提交 `9fb32f4` 入库。

---

## 二、修改汇总

| 字段 | 标签 | 修改类型 | 修改前 | 修改后 | 目的 |
|---|---|---|---|---|---|
| `UserName` | 使用单位名称 | 区域加高+加宽 | `{176,180,760,210}` | `{176,180,795,226}` | 覆盖折行的第二行名称 |
| `LayerStationDoor` | 层站门数 | 三区加宽 | `30 / 30 / 35` px | `45 / 55 / 65` px | 提高对两位数等横向偏移的容忍 |
| `Date` | 检验日期 | 去起始区+去“至” | 两区 + `trim` | 单区(270–400) + `removePrefix:"至"` | 仅保留“至”后日期 |

## 三、详细改动与验证

### 1. 使用单位名称（UserName）
- **原因**：长名称折行到第二行时，第二行中心点落在原 30px 单带 `[180,210]` 之外被丢弃，只识别到第一行（“结果不全”）。
- **改动**：区域下边界 `210 → 226`、右边界 `760 → 795`，覆盖两行单元格高度与全宽；下一行“统一社会信用代码/设备类别”中心 y≈235，靠中心点匹配被排除，不会误吞。
- **验证**：模拟“折行两行”名称 → 旧配置只取第一行、新配置取完整；单行名称仍正常。

### 2. 层站门数（LayerStationDoor）
- **原因**：三个区仅 `30/30/35` px 宽，且区之间留有 `45/55` px 空白间隙；匹配按中心点判定，若数值为两位数或整体偏移，中心易滑入间隙而整段漏识别。
- **改动**（y 范围不变 `635–660`）：
  - Z1：`{215,635,245,660}` → `{205,635,250,660}`（宽 30→45）
  - Z2：`{290,635,320,660}` → `{270,635,325,660}`（宽 30→55）
  - Z3：`{375,635,410,660}` → `{345,635,410,660}`（宽 35→65）
  - 各数值格覆盖全宽，但仍按中心点**精确排除** 层/站/门 标签。
- **验证**：三张测试图得到 `999` / `877` / `988`，标签未误入；单数字余量提升至 30–54px。

### 3. 检验日期（Date）
- **原因**：原配置取“起始日期 + 至 + 结束日期”整段，用户只需“至”后的结束日期且不含“至”字。
- **改动**：移除起始日期区（原 `130–250`），保留“至”所在区 `270–400`；`postProcess` 由 `trim` 改为 `removePrefix`，`removePrefix:"至"`。
- **验证**：三张测试图均得到 `2026年06月25日`（起始日期已丢弃、“至”已去除）。

## 五、EnableDetectSplit 引入的问题与修复（09e880c → 668b3a6）

### 1. 引入 EnableDetectSplit 的初衷（提交 09e880c）
- 层站门数成功率低：OCR 对「整图大、单字符占比小」的报告漏检（第二/三格无检测框）。
- 临时方案：全局 `EnableDetectSplit=true` + `IsWords=true`，层站门数 4/4 救回（如 `5//` → `5/5/5`）。

### 2. 副作用（双刃剑，整图级参数）
- `EnableDetectSplit` 改变**整图**切分粒度，破坏其它字段：
  - 额定速度 `1.75m/s` → `75m/s`（"1."被切丢）
  - 检验日期 2/4 图产生乱码（如 `日0自809202`）

### 3. 修复方案（提交 668b3a6）
- 全局请求**不带** `EnableDetectSplit`，保住 Speed / Date；
- 仅当层站门数三格出现空段（如 `5//`）时，对该行区域**裁剪放大 3 倍**，用带 split 的**局部请求**重试一次；
- 验证方式：用 Node 复刻 `ZoneOcrParser` 区域匹配（`verify_fix.js`），对比「无 split 基线」与「整图 split」两套现有 OCR 产物，模拟局部重试。结果：4 张测试图修复后三字段全部正确 —— 层站门数 `5/5/5`、`4/4/4`；额定速度 `1.75m/s`；检验日期 `2026年08月03日`。

### 4. 重试实现中的坐标 bug（本次关键修复）
- 现象：`TryRetryLayerStationDoor` 假设图像被归一化到 800×1100，用 `zx1 * imgW / baseW` 把裁剪框映射到图像 y≈579–630，**框到的是额定速度/载重量那一行**，而非层站门数行（层站门数「5」真实在图像 y≈652），重试得到 `kg/75/m/s` 而非 `5/5/5`。
- 根因：OCR 返回的是**原始图像坐标（1565×1020）**，`ZoneOcrParser` 也是直接用原始坐标匹配 zone；重试代码却多做了一次归一化映射，与解析器约定不一致。
- 修复：裁剪 / 匹配改为与解析器一致的**原始图像坐标**（去掉 `zx1 * imgW / baseW` 缩放），现已正确救回 `5/5/5`。

### 5. 连带编译错误修复（CS7036）
- `ip["X"]?.Value<int>()` 在 Newtonsoft.Json 里 `Value<T>()` 必须带 key 参数，无参调用报错 → 改为 `ip["X"]?.ToObject<int>()`。

## 六、待注意 / 后续
1. **单日期报告**：若报告检验日期为单日期、无“至”区间（如直接写 `检验日期：2026年06月25日`），该段通常落在更左侧（x≈136），当前 Date 区 `270–400` 会采不到 → Date 为空。如需兼容，可放宽 Date 区或加回起始区（仅在检测到“至”时走 removePrefix）。
2. **坐标缩放系统性隐患**：`ZoneOcrParser` 加载了 `imageWidth/imageHeight` 却**未做坐标缩放**，完全依赖上游把图片归一化到 800×1100。一旦归一化方式变化或某张图未经归一化直接送 OCR，所有区域坐标会整体偏移、全字段漏识别。建议给解析器加一层按基准尺寸的坐标归一化兜底。
3. **bin 副本**：`src/CYZLZDH.App/bin/{Debug,Release}/net472/OcrZoneConfig.json` 为构建产物（被 `.gitignore` 忽略），与 src 配置内容一致，重新编译会自动覆盖，无需手动维护。
